# Per-post approval checklist

Use one copy of this list for every external message, including Discord
moderator DMs. A previous GitHub or ClawHub approval does not cover community
posts.

## Identity

- Channel:
- Draft section in `launch-copy.md`:
- Intended publish time and timezone:
- Approver:
- Decision: approve / hold / rewrite

## Claims

- [ ] Uses only the fact card in `docs/community-launch-plan.md`
- [ ] States this is an RC
- [ ] Names supported adapters and the official LanceDB beta limit
- [ ] Mentions the LanceDB Pro 1,000-record export cap when the audience may
      use that source
- [ ] Avoids lossless, zero downtime, all versions, improves recall, one click
- [ ] Does not present the 1,500-record dogfood as a success rate

## Safety and privacy

- [ ] Single CTA: anonymized dry-run report via Issue Form
- [ ] Tells testers not to send memory, credentials, hostnames, or paths
- [ ] Does not attach or quote real exports
- [ ] Support stays on GitHub Issues, not in the destination thread

## Channel fit

- [ ] Platform rules re-checked on the day of posting
- [ ] Discord posts have moderator permission and a named channel
- [ ] V2EX text is maintainer-written, not model-generated
- [ ] Show HN title starts with `Show HN`, has a try-it path, and names no
      upvote request
- [ ] This exact text is not being cross-posted the same day

## After posting

- [ ] Tracker row filled in `docs/community-launch-plan.md`
- [ ] First replies watched for leaked secrets
- [ ] Stop conditions reviewed before the next channel
